# Windows 绿色版用户操作指南

> 适用版本：Windows Portable Build（`sparkflow.exe` + `cron-runner.exe` + `login-desktop.exe`，zip 解压即用，无需 Python/Node/Docker/WSL2）。
> 本文基于**当前绿色版实际实现**编写（非 GitHub README 内容），与源码仓库的 `webui/`、`core/`、`scripts/` 当前代码一一对应。

---

## 0. 先认识绿色版

```
DouYinSparkFlow-win64/
├── start.bat              # 一键启动（推荐入口）
├── stop.bat               # 停止后台服务
├── app/
│   ├── sparkflow.exe      # 主程序：Web 控制台（:8787）+ 发送任务（--doTask）
│   ├── cron-runner.exe    # 调度器：每分钟检查 app\state\cron\root 并触发任务
│   ├── login-desktop.exe  # 登录服务（:18090）：本机弹出扫码浏览器窗口
│   └── config.json / usersData.json / webui_settings.json / state/ / logs/
│                          # 所有运行数据都在 exe 旁，随目录整体迁移
├── chrome/                # 内置 Chromium（Playwright）
└── node/                  # 内置协议发送器（protocol-sender.exe）
```

三个 exe 的分工：
- **sparkflow.exe**：Web 界面 + 实际发消息（浏览器自动化）。
- **cron-runner.exe**：定时触发，只负责"到点执行 sparkflow.exe --doTask"。
- **login-desktop.exe**：扫码登录专用；空闲 30 分钟会自动退出（正常现象，登录时它才工作）。

---

## 1. 第一次启动：初始化管理员账号

1. 双击 `start.bat`（会启动 cron-runner 和 login-desktop，最后前台运行 Web 服务）。
2. 浏览器打开 `http://127.0.0.1:8787`。
3. 首次访问显示**「初始化管理员」**页面（login.html 的 bootstrap 表单）：
   - 管理员用户名（默认 `admin`，可改）
   - 管理员密码 + 确认密码（两次一致）
   - 点**「初始化管理员账号」**
4. 跳回登录页，用刚设置的账号密码登录，进入主控制台。

> 密码用 PBKDF2 哈希保存在 `app\webui_settings.json`，不存明文。

---

## 2. 添加并登录抖音账号

登录工作区在首页的**「交互式登录浏览器」**折叠区（扫码登录、登录态失效修复与账号同步）：

1. 展开该区，点**「添加新的抖音账号」**。
   - 绿色版会在**本机弹出一个 Chromium 窗口**（由 login-desktop.exe 拉起）并打开抖音创作者中心登录页；
   - 页面上的**「手机扫码登录」**区域会显示大图二维码（也可点「单独打开二维码」在新标签看大图）。
2. 用**手机抖音 App** 扫码并确认登录。
3. 扫码后等服务检测到已登录（页面状态会变化），点**「保存新账号登录」**。
   - 登录态（cookies）写入 `usersData.json`，账号出现在首页账号列表。
4. 登录窗口不用时点**「关闭登录界面」**；login-desktop 空闲 30 分钟也会自动退出。

另一种方式（CLI）：在绿色版 `app` 目录执行 `sparkflow.exe`，选菜单 **1. Add account login**，会直接弹浏览器扫码（适合本机操作）。

已有账号登录态失效时：在对应账号卡片点**「重新登录」**，走同一套扫码流程后点**「保存登录态」**（账号信息保持不变，只更新 cookies）。

---

## 3. 确认账号登录状态正常

没有"一键检测登录"按钮，按以下方式综合判断：

- **登录工作区状态**：展开「交互式登录浏览器」，状态区显示当前登录桌面是否在运行、是否已登录（用户名）。
- **账号卡片**：登录态失效的典型表现是——任务运行后该账号目标进入「失败/待核验」，失败原因为「登录失效」（`login_required`）。
- **发送控制台**：每个账号有状态徽标：`健康 / 待发送 / 注意 / 警告 / 已暂停`。
  - `已暂停` = 当天账号级失败达到阈值（默认 2 次），当天不再自动尝试，需处理后点「补发异常」或「重新登录」。
- **概览页**：关注「异常」计数；有异常时优先处理而不是等定时任务。

判断要点：**cookies 是否有效只能通过真实发送验证**。如果账号卡片上目标长时间「待核验/失败」且原因是登录类，就点「重新登录」走一遍扫码。

---

## 4. 刷新好友列表并选择要续火花的好友

1. 首页账号列表 → 展开目标账号卡片 → 找到**「好友选择器」**。
2. 点**「刷新好友」**：系统用该账号 cookies 打开一个后台浏览器抓取"朋友私信"列表（需要登录态有效，失败会提示）。
3. 刷新后在好友列表里**搜索并勾选**要续火花的好友；勾选会自动同步到上方「目标好友」文本框（每行一个）。
4. 点**「保存账号」**。

也可以不用选择器：直接在「目标好友」文本框手动输入昵称（每行一个）后保存。

> 好友列表抓取依赖抖音创作者中心页面结构（XPath/class 选择器）。如果抖音改版导致「刷新好友」失败，报错会直接显示在界面上——此时请手动在文本框输入目标好友昵称（任务发送时使用好友索引/会话缓存解析，不受影响）。

---

## 5. 设置哪些好友需要续火花

在账号卡片内：
- **「启用自动续火花」**复选框（保存后生效）——账号是否参与自动任务。
- **「目标好友」**列表——发给谁。只对列出的好友发送。
- 底部**「启用自动发送 / 停用自动发送」**按钮——运行时快速开关（等同于上面的复选框，无需进编辑）。

最小配置三件事：**账号启用 + 目标好友列表 + 发送窗口**。三者齐了，定时任务才会真正发消息。

---

## 6. 设置续火花的时间/调度

**页面**：首页底部**「运维操作」**区 → **「自动发送窗口」**输入框 → 点**「更新发送窗口」**。

**格式**：`起时:00-止时:00/间隔分钟`，整点起止，例如：
- `10:00-18:00/20m`：每天 10:00 到 18:00 每 20 分钟调度一次（18:00 再补一次常规、18:20 补一次"未发送兜底"）。
- 也可以只填固定时刻 `HH:MM`（如 `12:00`），此时每天只在 12:00 发一次。

**生效链路**（绿色版）：
```
Web「更新发送窗口」→ 写 app\config.json 的 dailySendWindow
                  → 写 app\state\cron\root（cron 格式文本）
                  → cron-runner.exe 每分钟重读该文件 → 到点执行 sparkflow.exe --doTask
```

**确认生效（三步）**：
1. 首页概览卡片「**下次自动触发**」显示下次时间（如 `08-23 10:00`）。
2. 打开 `app\state\cron\root`，应看到 3 行任务行（窗口内循环 + 结束时刻 + 未发送兜底），命令形如：
   `*/20 10-17 * * * cd /d "…\app" && "…\app\sparkflow.exe" --doTask >> logs\ops.log 2>&1`
3. 到点后看 `app\logs\scheduler.log`（cron-runner 输出 `run: …`）和 `app\logs\ops.log`（任务实际执行日志）。

> 修改窗口**无需重启** cron-runner（它每分钟重读 spool）；但 Web 服务需保持运行（窗口配置存在内存与 config.json 中，重启后 Web 启动时会自动把配置同步回 spool）。

## 7. 「补发全部对象 / 补发异常 / 补发待发送」分别是什么

系统有「强确认」机制：消息发出后必须拿到**强证据**（服务端回执或页面回显计数）才记为「已发」；证据不足的目标记为**待核验**，下次调度会**重新发送**（防止漏发，也可能重复发）。

| 按钮 | 位置 | 行为 | 什么时候用 |
|---|---|---|---|
| **补发全部对象**（run-now） | 首页顶部 | 绕过时间窗口，**对所有账号的全部目标**强制执行一轮（含已强确认的也会再发） | 配置变更后想立刻全量发一遍；**不要在刚配好目标前乱点** |
| **补发异常**（run-failed） | 首页顶部 / 发送控制台 | 只补发「待核验 / 失败 / 受账号异常影响」的目标 | 每天任务结束后有异常目标时补一轮 |
| **补发待发送**（run-unsent） | 发送控制台顶部 | 只补发「今日尚未强确认、仍在可重试状态」的目标（不含已失败、不含已强确认） | 窗口结束后想确认"今天该发的都发了"，最安全的一键补发 |

判断口诀：
- **今天还没到窗口/还在窗口内** → 什么都不用点，等定时。
- **窗口结束了，担心漏发** → 「补发待发送」（最安全）。
- **有目标失败/待核验** → 「补发异常」。
- **想无视窗口立刻全发** → 「补发全部对象」（慎用）。

每个按钮都有确认弹窗，会显示将影响的目标数量。

## 8. 启动后哪些服务必须保持运行

`start.bat` 一次启动三个，正常运行时：

| 服务 | 必须吗 | 停了会怎样 |
|---|---|---|
| **sparkflow.exe**（Web 前台窗口） | ✅ 必须 | 没有管理界面，也不执行任务；关掉它等于整个工具停止 |
| **cron-runner.exe**（后台） | ✅ 必须（要定时的话） | 定时调度失效；手动「补发」按钮不受影响（它们直接调 sparkflow.exe） |
| **login-desktop.exe**（后台） | ⚠️ 仅登录时需要 | 只在「打开登录工作区」时用到；空闲 30 分钟自动退出是正常行为 |

判断是否在运行：任务管理器看 `sparkflow.exe / cron-runner.exe / login-desktop.exe`；或 Web 概览页的「任务锁」状态；`logs\scheduler.log` 有内容说明 cron-runner 活着。

## 9. 第一次使用不要随便点的按钮

| 按钮 | 风险 |
|---|---|
| **补发全部对象** | 无视窗口全量重发，配置未就绪时会向所有目标发一轮消息 |
| **删除账号** | 不可撤销，连带删除该账号目标、发送账本与失败记录 |
| **强制重置工作区**（登录工作区内，admin） | 清空当前登录环境、切换队列下一位用户；登录到一半会被打断 |
| **关闭登录界面** | 未保存的登录过程作废（弹窗有确认，只是提醒） |
| **运行配置** 里的高级项（消息变体、间隔、协议发送开关等） | 改动影响全部账号的发送行为；**useProtocolSender 等保持默认即可**，协议路径出问题会走失败队列 |
| **设置页**里的系统路径/端口类字段 | 不了解含义时保持默认 |

原则：**先只动「账号 / 目标 / 发送窗口」三件事**，跑通一轮再研究高级配置。

## 10. 关机、重启、重新启动的正确操作

- **正常关机前**：Web 窗口按 `Ctrl+C` 停掉（或直接关机）。数据已实时落盘（`config.json`、`usersData.json`、`state\`、`logs\`），不会因强关丢失。
- **重启电脑后**：
  1. 如果上次没停干净，先双击 `stop.bat`（防止端口/锁冲突）。
  2. 双击 `start.bat`。
  3. 打开 `http://127.0.0.1:8787` 登录。
  4. **无需重新配置**：账号、目标、窗口、日志都还在 `app\` 下。
- **整体搬家**：整个 `DouYinSparkFlow-win64` 目录拷贝到新位置即可（所有路径都是相对 exe 的）。

## 11. 与 GitHub README 描述的使用方式差异（当前绿色版）

| 维度 | README/旧文档（Docker 版） | 当前 Windows 绿色版 |
|---|---|---|
| 部署 | Docker Compose 五容器（web/login-desktop/scheduler/task/proxy） | 三个 exe + start.bat，无 Docker/WSL2 |
| 登录 | noVNC 远程桌面（8788 端口，SSH 隧道）扫码 | 本机弹出 Chromium 窗口 + 页面大图二维码（18090 服务） |
| 调度 | 容器内 cron + `state/cron/root` 宿主共享卷 | `app\state\cron\root` + cron-runner.exe（每分钟重读） |
| 手动任务入口 | Web 控制台 | 相同（补发全部对象/补发异常/补发待发送），但**生成命令是 `sparkflow.exe --doTask`**（打包入口） |
| 数据目录 | 容器卷 /opt/douyin-sparkflow/state | **exe 旁** `app\`（config/usersData/state/logs 全在一起） |
| 协议发送 | Node 容器回退 | 内置 `node\protocol-sender.exe`（SEA 单文件） |
| GitHub Actions | 每日自动跑一次 | 绿色版没有（本地调度替代） |
| 端口 | 8787 / 8788 / 7890 / 9090 | 只有 **8787（Web）** 与 **18090（登录服务，仅本机）** |

## 12. 已知问题 / 限制（当前实现）

1. **`/login-desktop/proxy/vnc.html` 显示 502 —— 可以忽略**。该地址是 Docker 版 noVNC 桌面代理，Windows 原生模式**没有 noVNC 后端**，前端 iframe 加载它必然 502。**Windows 正确的登录方式**：登录工作区 → 「添加新的抖音账号」→ 本机弹窗 + 页面二维码 → 手机扫码 → 「保存新账号登录」。二维码、状态、保存功能都走 18090 服务，与 noVNC 无关。
2. **好友列表刷新依赖抖音页面结构**（XPath/带哈希 class）：抖音创作者中心改版后「刷新好友」可能失败，此时手动填写目标昵称（任务发送端有自己的会话缓存解析，不依赖该选择器）。
3. **强确认机制**：发送后若无强证据（服务端回执或页面回显），目标进入「待核验」，下一轮调度会**再次发送**——可能导致同一目标当天收到 2 条消息（设计如此，防漏发优先）。
4. **登录态过期**：cookies 失效时任务会记「登录失效」失败；需要「重新登录」扫码。无自动续期。
5. **login-desktop 空闲自动退出**（30 分钟）：登录窗口开着不用会被关闭，属正常；重新点「添加/重新登录」会再拉起。
6. **`usersData.json` 手工编辑**：必须用 UTF-8 **无 BOM** 保存（带 BOM 会解析失败）；不建议手工编辑，都在 Web 界面操作。
7. **Windows 安全策略**：未签名的 exe 可能被 SmartScreen/AppLocker 拦截（本机测试环境实测：直接双击/命令行运行正常，个别 PowerShell `Start-Process` 场景会被拦）；如遇拦截请放行或右键"仍要运行"。
8. **默认发送窗口**：首次运行（无 config.json）默认 `10:00-18:00/20m`，请按自己需要修改。
9. **多账号并发**：默认 `taskCount=1` 顺序执行；增大并发请确认网络与风控承受能力（工具自带免责声明，风险自担）。
10. **代理（Mihomo）**：绿色版未内置代理服务；需要代理请在「运行配置」的 `proxyAddress` 配置或环境变量层处理。

## 13. 定时任务配置速查（设置 → 确认 → 排障）

**在哪设置**：首页 → 底部「运维操作」→「自动发送窗口」→ 输入 → 「更新发送窗口」。

**设置什么**：`起时:00-止时:00/间隔分钟`，例如 `10:00-18:00/20m`。

**设置完成后如何确认真的生效**：
1. 首页概览「下次自动触发」有具体时间（如 `08-23 10:00`）。
2. `app\state\cron\root` 有 3 行任务（窗口循环 + 结束时刻 + 未发送兜底），命令含 `sparkflow.exe --doTask`。
3. 到点后 `app\logs\scheduler.log` 出现 `run: …sparkflow.exe --doTask …`；`app\logs\ops.log` 出现本次任务日志（`Starting tasks with config` / 各账号发送结果）。

**排障**：
- 概览无「下次自动触发」→ 窗口未保存成功或 cron-runner 未运行（`logs\scheduler.log` 应有 `watching` 行）。
- scheduler.log 有 `run:` 但 ops.log 没新记录 → 命令执行失败，检查 `cd /d` 路径与 sparkflow.exe 是否被安全软件拦截。
- 到点没触发 → 确认 `state\cron\root` 内容与系统时间（时区跟随 Windows 系统时区）。
